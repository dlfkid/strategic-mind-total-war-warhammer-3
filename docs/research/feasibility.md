# 第一轮技术可行性报告

日期：2026-10-14。项目背景见 [设计原则](../design-principles.md)，全部来源编号见 [调查来源](sources.md)。本报告支持继续进行小规模实机实验，尚不足以承诺完整战略引擎。

## 结论与当前版本

截至调查日，官方已发布 9.0.3（S01）。9.0 已调整 Campaign AI 招募历史、任务管理与部分派系战略行为（S02）；这会影响集结和空转的基线。9.0.3 仍包含任务重载与胜利目标修正（S01）。不能以旧教程描述的问题或旧镜像接口直接宣称当前版本可控。

鲍里斯当前原版战役已包含野兽人计划与威胁报告（S03）。MVP 必须识别这些原版触发，不可将原版通知或出征误记为 Strategic Mind 的成果；它们同时是寻找真实事件输入的调查线索。

本机没有取得游戏安装与构建信息。以下游戏能力全部处于 `DOC` 或第三方 `SOURCE`，**没有任何 `GAME` 通过记录**。

| 方向 | 初步判断 | 进入开发所需的下一项证据 |
| --- | --- | --- |
| 真实事件与有限历史记忆 | 有可用候选基础 | 事件上下文、去重、存档往返 |
| 原版消息战略纪事 | 值得优先验证 | 本地化、消息类型、战争迷雾及重载后去重 |
| 战略态度/性格调节 | 文档明确列出干预入口 | 读回、时效、行为影响、恢复和与原版脚本共存 |
| 指定军队局部行动 | 有命令与 AI 移动接管候选 | 正确阶段执行、路径/行动点、归还和死锁测试 |
| 多军团长期自主计划 | 未确认通用规划器入口 | 先证明单军团闭环，再研究协调 |
| 自定义使命 | 有任务构建入口 | 实机显示、进度及保存恢复 |
| 正式战役胜利与 Steam 成就 | 有胜利类型入口，成就条件未知 | 分别核对当前原版流程并实测 |
| 普通战役战斗的通用 AI 改造 | 脚本能力存在，普遍接入未证实 | 不替换大型默认脚本的加载实验 |

## 工具链

采用“合法取得的当前游戏数据 + RPFM + 原版脚本 + 最小测试包”。RPFM 用于读取/编辑包、查看 DB 与本地化，Assembly Kit 的定义供对照；不要误认为必须完整安装地图工具才能做脚本实验。RPFM v5.2.0 于 2026-10-13 发布，作者提供 Windows/Linux 资产（S13）；本机不具备已经跑通的工具链。

未来先从当前安装核实 Mod 脚本入口、Lua 环境和日志开关，再确定打包方式。镜像记载 Lua 5.1（S15），建议先使用兼容子集。脱离游戏的 Lua 测试只能覆盖纯逻辑，不能模拟引擎调度。三种包独立构建；当前不添加语言依赖、打包器或 CI。

## 战略 AI：倾向、限制与直接命令

下列候选入口来自 S05、S06，详细方法与测试登记在 [API 表](api-register.md)。

| 控制方式 | 候选入口 | 含义与限制 |
| --- | --- | --- |
| 倾向 | `cm:cai_strategic_stance_manager_promote_specified_stance_towards_target_faction` | 提升一种派系间战略态度的选择倾向，不等于设置具体军队目标 |
| 性格 | `cm:force_change_cai_faction_personality` | 换用 DB 性格；无法据此保证某项行动，且可能被其他脚本再更换 |
| 脚本上下文 | `cm:cai_set_faction_script_context` | 依赖 DB 预设响应；不是任意命令通道，不能凭名称臆造含义 |
| 地点提示 | `cm:cai_add_point_of_interest_generic_marker` | 地图兴趣点候选，行为依赖 DB 对组编号的配置，不能直接等同军队目的地 |
| 硬限制 | `cm:force_diplomacy` | 控制外交选项可否提出/接受，名称不代表立即签订协议 |
| 状态强制 | `cm:force_declare_war` | 直接改变外交状态，不能拿它证明 AI 自主决策 |
| 局部命令 | `cm:move_to`、`cm:attack` | 下达行动请求；不承诺合法路径、可用行动点、完成或后续计划延续 |
| 控制权协调 | `cm:cai_disable_movement_for_character` / `cm:cai_enable_movement_for_character` | 文档描述为暂停/恢复 AI 移动控制；接管和归还必须成对验证 |

战略态度与外交界面关系分数不是同一变量。应分别读回态度、检查外交状态和观测军队，不能互相代替。派系对的清理函数可能清除其他脚本的设置；首个实验尽量使用可到期的局部干预，不在共存环境中调用全量清理。

S07 的 AI 模型接口列出态度/倾向读回，有利于区分“请求已提交”与“设置已经反映到模型”。同一文档的战争协调接口只列出 favour points 读写；虽然存在协调事件，当前材料不足以认定有通用的军团集结命令。

### CAI 数据表

已在 RPFM `schema_wh3.ron` 固定快照中确认以下表结构名称（S14），**未读取游戏内记录**：

| 表族举例 | 调查用途 | 本次不能证明的事项 |
| --- | --- | --- |
| `cai_personalities_tables`、`cai_personality_strategic_profiles_tables` | 性格与战略配置关联 | 鲍里斯当前使用哪个性格，以及某字段实际生效 |
| `cai_personality_diplomatic_events_tables` | 历史事件对外交的候选映射 | 当前合法事件 key、权重、衰减和叠加方式 |
| `cai_personalities_personality_variable_profile_context_overrides_tables` | 脚本上下文与配置关系 | 某上下文是否被原版或其他 Mod 占用 |
| `cai_military_behaviour_policies_tables`、`cai_personalities_task_management_system_task_generator_profiles_tables`、`cai_task_management_system_task_generators_tables` | 军事行为/任务配置调查 | 能否运行时指定单支军队的目标或协调多军团 |

下一步在当前版本追溯一个现有性格到它的关联记录，记录字段、引用、原值与默认值；实验一次只改变一个变量。自定义 key 优先，必须覆写原版记录时记录完整冲突面。表名存在不意味着可重写引擎算法。

## Strategic Chronicle 与 World Memory

事件注册由 `core:add_listener` 支持（S08）。S07 列出外交、战后、劫掠/夷平及移动事件与可见性读取；缺少某种事件时，可对选定对象做回合状态差分，但快照差分不能自动恢复期间的全部因果。

存档可研究 `cm:save_named_value` / `cm:load_named_value` 与保存/加载回调（S05）。首版只保存简单数据，设置版本和容量；不序列化游戏对象。消息优先 `cm:show_message_event`，消息类型索引和本地化 key 从当前游戏核对（S05）。

角色可见性是 Chronicle 的一个门槛，不是通用知情证明。事件回调不保证人类看到了它；“地图曾探索”也不等于“当前敌军可见”。每个玩家有单独披露账本，未知时不显示，调试信息不进入玩家文本。

日志可尝试经 `out` 输出带固定前缀的结构化文本（S09）。零售环境是否落盘、需要哪些开关、文件位置与缓冲行为未测试。先证明一个标记能在实际日志中找到，再建立解析器；不默认任意文件 I/O、JSON 库或外部执行桥可用。

原版消息能否满足历史浏览、关闭通知和筛选要分开验收。第一版允许用配置关闭本 Mod 新消息，用原版历史查看已发布消息；独立历史筛选界面后置。

## Victory Conditions

S10 提供脚本目标、`mission_manager:set_victory_mission`、`mission_manager:set_victory_type`，并列出 `game_victory` payload；S14 中有 `victory_types_tables`、`campaign_victory_conditions_tables`。这支持“研究正式胜利接入”，不等于已经知道 9.0.3 的完整触发链。胜利任务构造与 payload 的当前用法先查原版实例，不能只设置类型就判定胜利已触发。

分别验证使命进度、胜利面板、正式胜利状态/事件、继续战役行为以及对应 Steam 成就。需要追踪当前版本原版胜利脚本和已有任务，防止双重注册、旧胜利抢先结束或重载后丢进度。不能因为有 `award_achievement` 就认为应主动调用或能替代正常成就流程；本阶段不修改玩家成就。

若正式胜利接口无法稳定共存，可以先发行明确标注的额外使命模式，并说明未替换原版胜利。成就兼容未知时保持未知，不因使用 Mod 就断言一定禁用或一定可获得。

## Battle AI

S11 描述战斗脚本与 battle setup 的关系，S12 支持单位接管/归还和命令。它们适合限定场景实验，但尚未证明能安全接入每一场普通野战和攻城战，也未证明接管后可保留原版完整 AI 行为。

首个战斗实验应只控制一个 AI 远程单位，再交还原版 AI。之后才能评估防骗箭、威胁识别、骑兵、炮兵保护、预备队和攻城反击。若加载需要替换大型默认脚本或控制无法可靠归还，缩小到脚本战斗/限定场景。未找到的内部感知、寻路或目标函数不编造接口。

## 风险与继续投入条件

主要风险依次为：旧文档与当前构建错位；调用接受但行为未变；与原版/其他 Mod 争夺控制；秘密历史通过消息泄漏；存档实体变化与重复执行；事件/记忆无界增长；正式胜利与成就链不同；平台补丁或工具能力差异。

继续 Campaign AI 至少需要可靠世界读取、有限事件/历史持久化、一种有可观测反馈且可恢复的行为干预。完整纪事还需要可靠的玩家可见性与消息通道。拿不到干预能力时降为观察/纪事项目；只有强制命令有效时定位为有限脚本导演；不能以消息能显示就声称战略引擎可行。

具体通过阈值、实验预算与失败后处理见 [MVP](../mvp-boris.md)，发布前检查见 [兼容性与测试](../testing-and-compatibility.md)。
