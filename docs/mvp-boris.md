# MVP：鲍里斯与野兽人的冲突

状态：计划，所有实机实验 `NOT_RUN`。目标是在实际超凡帝国战役中证明一条小而完整的因果链，再决定战略引擎的投入规模。

## 场景与范围

玩家控制能观察米登领局势的派系，鲍里斯所属派系由 AI 控制。只跟踪一组已核对的米登领地区、一个野兽人威胁与一支现有 AI 军团。先核对当前版本鲍里斯的角色、派系和原版机制；[官方新内容](research/sources.md) 已改变早期版本背景，不能硬编码旧 key 或假定其不具备独立机制。

原版已包含野兽人威胁报告。先记录这些机制在 AI 控制下是否运行、会否分派行动，以及相关脚本/消息 ID；对照组保持相同原版机制。不能将它们的通知或行为当成本 Mod 的执行证据。

不要求玩家拥有全体 DLC；先记录测试机实际 DLC 和该存档中对象是否存在。若鲍里斯不存在、被合邦或已由人类控制，记录条件不满足，不生成替代军队，不把其他将领冒充鲍里斯。

理想输入是最近 8 回合内、米登领或已明确配置的相邻地区发生的至少两次独立野兽人劫掠/夷平事件。必须能确认行为方、地点与发生时间。若存档只有一次真实受袭，就缩为“单次受袭反应实验”，不用“持续袭击”文案；如只有敌军靠近，只能称为“邻近威胁实验”。

## 决策与因果要求

先以真实事件形成记忆，常识层检查合法性、核心安全和风险，帝国理念增加领土防御价值，鲍里斯性格增加对野兽人的优先级。输出一个有期限的“应对该威胁”意图，附继续/终止条件。

评估策略时保留同世界快照的无记忆对照：移除受袭记忆后，目标选择或优先级必须发生预先定义的差异；只改变纪事措辞不算通过。比较三层各自的贡献，但不为实验制造事件。

将内部原因与执行证据分开保存。软倾向被设置后观察到军队行动，只能证明干预后的行为；若没有更多证据，不能断言原版 AI 正因本 Mod 而行动。通过对照增强证据，玩家叙事仍只使用足以支持的事实。

## 顺序实验

### E0：环境与最小加载

需要游戏主菜单版本、平台、Build ID、DLC、Mod 列表和加载顺序，当前安装中的相关 Lua/DB 数据以及一份可重复加载的测试存档。

核对脚本入口、Lua 版本、命名空间与日志输出。最小包只输出一次加载标记。新局、旧档各加载一次；结果写 API-01、API-07。不进入后续实验，直到能看见明确、可检索的加载和失败信息。

### E1：观察、记忆、存档和消息

只观察真实事件，记录一次受袭和一份选定对象状态。序列化、保存、退出、重载后，事件 ID、关系摘要和去重标志一致。验证观察者已探索但无视野、当前有视野、隐藏敌军与失去视野几种情况。

先发送一条与玩家已知事实有关的原版消息，验证本地化、持久历史、关闭新通知和读档不重复。此步验证 Memory/Chronicle 基础链路，**没有行为干预，不能算完整战略 MVP**。对应 API-02–07。

### E2：一次软倾向干预

选用 API-08 的有回合边界的 stance promotion 候选。先核对参数与可用 stance，在干净存档中对一个方向、一个派系对提交一次；请求与意图使用同一关联 ID。读回实际 promotion 配置和后续态度，再观察 5 个完整 AI 回合。

对照组使用同一前置存档与相同玩家操作，不提交这次干预。记录行动、招募、位置、受袭事件、目标变化及其他原版机制。优先跨 3 个不同前置局面做配对观察，而非把同一随机状态的重复读档视为独立样本。小样本只用于初步判断，不能宣称统计证明。

到期后检查残留、重复设置和性能。不要用 `clear_all_promotions_between_factions` 假设只清除本 Mod 状态。若效果无法读回或没有明显行为变化，结果可以是 `INCONCLUSIVE`；不能把沉默当作成功。

### E3：有限行动接管备选

若 E2 只能证明态度变化，单独执行 API-10，关闭 E2 干预。选择一支现有、可行走、在正确回合且具有足够行动点的 AI 军团；先只试一次合法短距离移动，不以传送或补充行动点模拟成功。

暂停该角色的 AI 移动控制，提交命令，观测位置/事件，并在完成、失败或超时后归还。不得永久关闭整个派系的 AI。验证路径不可达、目标消失、军队受伤/被毁、保存加载中断和意外异常；每条退出路径都必须归还或在下次加载时安全恢复。确认归还后原版 AI 又能行动，再考虑一次合法攻击。

这项通过证明“有限脚本行动”能力，不能称作“AI 自主采纳战略”。若归还不可靠或出现软锁，停止接管路线，保留只读模式。

### E4：观察后纪事

只在玩家实际可见相应军队/行动、且叙事涉及的历史事实也可披露时发布。事件发生回合、结果观测回合、该玩家首次获知回合分别保存。隐藏期间不弹窗、不标记地点、不在摘要泄密。

局部命令有明确关联且完成时，可以把受袭记忆、决策和结果连成故事。若只证明军队在当地活动，则纪事只陈述活动，不编造讨伐目的、秘密目标或胜利。玩家看见军队不自动赋予其读取秘密意图的资格。

示例文案仅为文案草案，不能当作已发生事件：“你在米登领边境发现了鲍里斯的军队。”只有可披露的记录确认该地区受袭，才加入对应历史；只有执行证据支持时才使用“讨伐开始”等措辞。

## 最小记录格式

下面是设计字段，尚未产生真实运行数据。首版用基本值表持久化，结构化日志经已验证的输出通道记录。

| 记录 | 必要字段 |
| --- | --- |
| 世界事件 | `event_id, event_type, occurred_turn, actors, location, evidence_refs` |
| 记忆/决策 | `memory_ids, decision_id, state_summary, layer_reasons, chosen_goal, expires_turn` |
| 执行请求 | `request_id, decision_id, api_id, arguments, submitted_turn, timeout_turn` |
| 结果观测 | `observation_id, request_id, observed_turn, expected_effect, actual_effect, attribution` |
| 玩家获知 | `observer_faction, observation_id, learned_turn, visible_fact_ids, redacted_fields` |
| 消息 | `chronicle_id, observer_faction, fact_ids, decision_id, template_key, emitted_turn` |

执行状态包括 `intent_created` → `request_submitted` → `world_observed`；失败分支记录 `failed`、`timed_out` 或 `inconclusive`。玩家披露另记 `player_observed`、`chronicle_emitted`。`world_observed` 只表示观察到预期世界变化，不自动证明因果归属；`attribution` 明记 `direct_command` 或 `uncertain` 等依据。

以 `[SM]` 为固定日志前缀，每行记录运行 ID、顺序号、回合、组件、状态与关联 ID。JSON 编码或其他格式须确定转义规范；不假定游戏自带 JSON。玩家文本不读取完整 debug 输出。

初始工程预算提案：最多 256 条原始事件、32 个关系摘要、8 个活动意图、64 条本 Mod 披露摘要；原始事件默认保留 20 回合，仍被活动决策引用的原因先归档为有界摘要再裁剪。最多维护一个被接管对象，不做全地图每帧扫描。数值是待测预算，不能视为性能结果。

## 通过、缩小范围与止损

| 决策 | 条件 |
| --- | --- |
| 值得继续局部 Campaign AI | E1 稳定；记忆对决策的对照成立；E2 至少观察到可读回的干预且局面比较有重复行为证据，或 E3 有可靠局部行动与归还；E4 无信息泄漏 |
| 只继续“倾向调节” | E2 的设置/到期可确认，但不能稳定指定行动；明确只承诺倾向，不扩大为多军团指挥 |
| 改为“有限脚本导演” | 只有 E3 工作且恢复可靠；以限定场景发布，明确不是自主规划器 |
| 改为“观察与纪事” | E1 可行，但所有低冲突干预均无可靠结果；不能声称完整战略引擎成功 |
| 停止或重设方案 | 无法可靠读状态/存档；控制无法归还；无法区分可见性却必须披露秘密；出现重复软锁/崩溃 |

建议第一轮实机探路限两次各约两小时的测试时段，先解决加载、日志、可见性与一次干预；不要用这个预算承诺全部行为对照完成。接着最多做 3 组前置局面的配对行为观察，再审查投入。仍无稳定控制证据时收缩范围，不无限调整权重。

原型验收至少覆盖一次真实事件、保存/退出/读取、一个可恢复干预、预期结果的独立观测，以及一条正确延迟披露的纪事。再以多个局面复核。没有干预的 E1 演示只证明子系统，不足以通过整体 MVP。

## 必须由实际游戏完成的部分

引擎阶段/排队语义、AI 是否采纳与覆盖命令、可达性和行动点、战后上下文生命周期、伏击可见性、消息渲染、落盘日志、存档恢复、回合耗时、长期稳定性、DLC 条件及 Steam 成就均需要测试机。自动化可整理、分析和重放纯逻辑，不能用 Mock 代替这些证据。
